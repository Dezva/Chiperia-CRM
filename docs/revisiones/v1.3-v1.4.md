## Guía incremental

Para una instalación que ya tiene 011, aplicar **únicamente**, en este orden, en el proyecto independiente de El Viejo:

1. `database/012_catalogo_individual.sql`
2. `database/013_metricas_ia.sql`
3. `database/014_avisos_pedidos.sql`

Después actualizar backend y frontend juntos. No volver a ejecutar 007–011: reemplazan funciones de versiones anteriores. Para una instalación completamente nueva, seguir la lista completa de [instalación](../instalacion.md).

Las migraciones son transaccionales y reejecutables. 012 respalda el catálogo en `viejo_catalog_backup`; 013 solo añade telemetría protegida; 014 solo añade lectura de pendientes. No se ejecutaron remotamente. Antes de una actualización real, conservar el respaldo habitual de la base independiente y verificar el catálogo convertido en esa copia.

No se publicaron entornos, no se tocó `main`, Guarnipitan ni producción y no se habilitaron servicios reales. No se añaden dependencias. Las variables existentes de proveedor/modelo se conservan; no se requieren claves para la demo.

## Compatibilidad comercial

Los 31 registros conservan sus IDs y precios, incluidas ediciones. Las variantes siguen siendo registros vendibles individuales. El precio de una categoría no existe. Los tres panes dulces permanecen sin precio e inactivos. Facturas genérica, si conserva ese nombre, conserva ID/precio histórico y queda retirada de nuevas ventas; no se transforma automáticamente en variedades. Los productos agregados por el encargado tienen sus propios IDs y precios.

No se reescriben líneas de pedidos ni carritos. Los artículos agotados, retirados o desactivados se vuelven a validar antes de nuevas solicitudes y aceptaciones; los carritos anteriores que los contienen requieren revisión. Cambiar de categoría no modifica un pedido histórico. El cálculo automático de chipería, delivery manual, recotización y confirmación humana se mantienen. Buffet conserva categorías fijas e importes acordados por el encargado.

Más detalles: [catálogo y sinónimos](../catalogo-v13.md), [optimización y métricas](../optimizacion-v14.md), [alertas](../alertas-v14.md).

## Windows: actualizar D:\chiperia

En PowerShell, comprobar primero el estado. Si aparecen cambios propios sin guardar, conservarlos antes de cambiar de rama; estos comandos no los descartan.

```powershell
Set-Location D:\chiperia
git status --short
git fetch origin
git switch feat/catalogo-alertas-v1.3-v1.4
git pull --ff-only origin feat/catalogo-alertas-v1.3-v1.4
corepack enable
pnpm install --frozen-lockfile
pnpm build
```

`git switch` crea el seguimiento de la rama remota en el primer uso. Si la rama local ya existe, cambia a ella. Mantener archivos de configuración y credenciales locales fuera de Git. No cambiar las puertas de activación de servicios.

Para revisar la demo:

```powershell
pnpm dev
```

Abrir `http://localhost:5173`. La demo guarda datos ficticios en el navegador y convierte una demo anterior conservando sus registros. Los cambios del navegador no son cambios en la base real. El servidor estático no sirve las Functions de Netlify; una instalación conectada requiere su backend habitual actualizado y las migraciones anteriores.

Para ejecutar las pruebas en Windows, ajustar la ruta si Chrome está instalado en otro lugar:

```powershell
$env:CHROMIUM_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
pnpm build
pnpm test
node scripts/compare-context.mjs
```

Si Corepack no puede activarse por permisos, usar `npx pnpm@11.25.0` en lugar de `pnpm`. No hay comandos de borrado, restablecimiento forzado ni reemplazo de datos.

## Limitaciones restantes

- Medialuna, Bollo y otras variedades deben ser creadas/revisadas por un encargado con su precio individual. No se infiere desde Facturas.
- La equivalencia comercial debe estar registrada o ser una variación gramatical inequívoca. No se aceptan aproximaciones gastronómicas ni sinónimos inventados por IA. Giros no verificables piden aclaración o atención humana.
- La búsqueda puede ampliar a todo el catálogo compacto; en esos casos la reducción es menor y puede requerir una segunda llamada.
- Métricas almacenan solo consumos informados. Un fallo de telemetría no interrumpe el pedido y puede dejar un registro ausente; no se vuelve a llamar al modelo por ese motivo.
- Los avisos funcionan con el CRM abierto y el intervalo del navegador. Su lectura/preferencia se recuerda por navegador/cuenta; no es una bandeja compartida ni notificación push. Audio físico y restricciones de móviles reales requieren prueba manual en el dispositivo.
- No se probaron Supabase, Meta ni OpenAI reales. El reconocimiento de fotos y el transporte fueron simulados. Activarlos sigue fuera de esta entrega.
