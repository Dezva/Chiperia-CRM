# Auditoría V1.1 antes de modificar código

Base local y remota verificada: a0bb1a23fc89637d2cf12748b227538b7f41e1c8. Solo existen main (c7df37f) y feat/el-viejo-villeta-v1 en el remoto al iniciar. Rama nueva: fix/el-viejo-v1.1. Checkout limpio; sin acceso a datos de Guarnipitan.

Problemas confirmados por lectura:

- CI usa ubuntu-latest con playwright-core 1.58.2. Se fijará Ubuntu 24.04. La consulta del run 44813213851 por GitHub CLI/API fue rechazada con Forbidden; el fallo concreto de Ubuntu 26.04 es evidencia aportada por el usuario, no log remoto leído en esta sesión.
- guarni_finish cambia p_kind de submit a human antes de limpiar draft_location_id: el buffet conserva la referencia residual. Release ya limpia el punto, pero se necesita que cada registro de solicitud lo limpie en la misma transacción, sin depender de una futura reactivación.
- Cambiar a retiro limpia el JSON del motor pero no siempre el campo SQL; cambiar de servicio puede restaurar una ubicación desde saved_carts. Se cubrirán ambas rutas.
- No existe menu_editor; interfaz, reconocimiento y RPC limitan menú a administradores.
- El worker vuelve a consultar menús por mensaje, pero descarga fotografías y versiones históricas innecesarias. El campo service no está en el SELECT del catálogo: el motor filtra por service y el chatbot real de chipería recibe un catálogo vacío. La demo no detectaba este fallo porque incluye service.
- Visión acepta campos incompletos/coerciones sin validar estrictamente respuesta, estado de truncamiento o rechazos del proveedor. El caché no distingue cambios de modelo y la escritura no resuelve duplicados concurrentes.
- El API general devuelve Base64 de hasta 90 menús. Se separará lectura de fotos autenticada y se preparará Storage privado mediante activación explícita, manteniendo fotografías históricas.

Se conservarán reglas de precios, cola, Auth, RLS, revisiones de atención y pruebas existentes. Migración incremental; no reejecutar migraciones históricas en instalaciones existentes. Sin conexión real a IA, Storage alojado o Meta.

Hallazgo durante la prueba integrada: JSONB reordena claves de los productos, mientras el motor comparaba serializaciones JSON completas; esto podía impedir que un carrito real saliera de la revisión de cotización. Se corrigió comparando campos explícitos y se cubre con worker + PostgreSQL y una prueba unitaria de claves reordenadas.
